Decoupled ScriptableObject Graph

Each phase in BossPhaseStats.cs declares a direct reference to its succeeding phase via public BossPhaseStats nextPhaseStats. The state machine monitors remaining health; when current phase health reaches 0, the boss does not instantiate a separate entity—it transitions cleanly into BossStaggerState and loads the next phase asset.

State Machine Event Log

Key Architectural Benefit: Weapon colliders are toggled via sub-frame animation events in AttackColliderHandler.cs, ensuring damage can only trigger during the active physical swing arcs, eliminating phantom hitbox clipping.

FSM State Transition Topology

The BossStateMachine inherits from a shared base state machine architecture, decoupling NavMesh pathfinding from animation crossfades and hitbox timings.

1. BossIdleState
Evaluates distance to Player. If player is within detection radius, computes NavMesh trajectory and transitions to Move.
2. BossMoveState
Executes pathfinding via NavMeshAgent using PhaseSpeed. When in melee or special attack range, switches to Attack.
3. BossAttackState
Sequences light vs heavy attacks based on lightAttacksBeforeHeaveyAttacks. Triggers animation hash and collider frames.
4. BossImpactState
Handles hit recovery when receiving player thrust or heavy blows without crossing stagger threshold.
5. BossStaggerState
Invoked when stagger meter hits PhaseStaggerNeeded. Boss is incapacitated for vulnerable counter-attack window.
6. PhaseTransition
Triggered on 0 HP. Replaces weapons, updates speeds/combos via nextPhaseStats, and triggers transition sequence.

    // Linked graph of phase data
    [field: SerializeField] public BossPhaseStats nextPhaseStats { get; private set; }
    [field: SerializeField] public BossTransitionPhase bossTransitionPhase { get; private set; }
    
    [field: SerializeField] public int startingPhaseHealth { get; private set; }
    [field: SerializeField] public List<BossAnimationSequence> normalAttacks { get; private set; }
    [field: SerializeField] public List<BossAnimationSequence> specialAttacks { get; private set; }

NPC Interaction & Turn-in Pipeline

When the player interacts with an NPC, the NPC enters NPCDialogState, executes FacePlayer(), triggers the talking animation blend, and evaluates quest conditions upon conversation termination.

Player Interaction
Player presses [E] via Unity Input System InputReader.InteractionEvent. NPC transitions from NPCIdleState.
NPCDialogState.Enter()
Calls FacePlayer(). Crossfades into TALKING_ANIMATION_HASH. Registers DialogueComplete callback.
NPCDialogState.Exit()
If PlayerHasQuestsReadyToTurnIn(), grants rewards and turns in. Else if HasQuestToGive(), transfers quest.

ADDITIONAL SYSTEMS AUDIO & COMBAT UTILITIES

Supporting Gameplay Subsystems

Modular helper engines authored to support real-time combat feel, audio spatialization, and targeting.

SoundFXManager.cs
Instantiates transient spatial AudioSources dynamically at world positions. Plays pitch-randomized sound effects and disposes game objects cleanly upon clip.length expiration to prevent memory leaks.
AttackColliderHandler.cs
Tied directly to animation event curves. Toggles damageDealingCollider.enabled only during the active strike window to ensure zero ghost hits or double-hit registration on a single swing.
TargetSeeker.cs
Manages lock-on targeting with Unity Cinemachine. Evaluates nearest viable targets within range, dynamically populates CinemachineTargetGroup, and detaches upon Health.OnDeath events.
